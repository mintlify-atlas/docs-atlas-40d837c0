---
title: "Set up and run Virtual Catalog locally from scratch"
description: "Configure Firebase and Cloudinary, install Flutter dependencies, and run your first Virtual Catalog storefront locally in six straightforward steps."
---

Virtual Catalog runs on Flutter 3.x and Firebase, so before you start you need the Flutter SDK installed on your machine, an active Firebase project, and a Cloudinary account with an upload preset configured. Once those are in place, you can have a working storefront running locally in a single terminal session.

<Steps>
  <Step title="Clone the repository">
    Clone the Virtual Catalog repository and move into the project directory.

    ```bash
    git clone https://github.com/Andzzio/virtual-catalog.git
    cd virtual-catalog
    ```
  </Step>

  <Step title="Install Flutter dependencies">
    Fetch all Dart packages declared in `pubspec.yaml`, including `firebase_core`, `cloud_firestore`, `flutter_dotenv`, `provider`, `go_router`, and the rest of the dependency tree.

    ```bash
    flutter pub get
    ```
  </Step>

  <Step title="Create the environment file">
    Virtual Catalog reads credentials at startup from a file named `env` in the project root (no extension). The app loads this file as an asset via `flutter_dotenv`, so the filename must match the asset path declared in `pubspec.yaml`.

    Create the file and add your three credentials:

    ```bash
    CLOUDINARY_CLOUD_NAME=your_cloud_name
    CLOUDINARY_UPLOAD_PRESET=your_upload_preset
    API_KEY=your_api_key
    ```

    | Variable | Where to find it |
    |---|---|
    | `CLOUDINARY_CLOUD_NAME` | Cloudinary Dashboard → Settings → Account |
    | `CLOUDINARY_UPLOAD_PRESET` | Cloudinary Dashboard → Settings → Upload → Upload presets |
    | `API_KEY` | Cloudinary Dashboard → Settings → Access Keys |

    <Warning>
      Never commit the `env` file to version control. Add it to `.gitignore` before your first commit.
    </Warning>
  </Step>

  <Step title="Connect Firebase">
    Initialize Firebase in the project. The FlutterFire CLI writes platform configuration to `lib/firebase_options.dart`, which `main.dart` imports at startup.

    ```bash
    firebase login
    firebase init
    ```

    When prompted, select **Firestore**, **Authentication**, and **Hosting**. The project ID is `catalogo-virtual-app` if you are connecting to the existing Firebase project, or enter your own project ID if you created a new one.

    ```bash
    flutterfire configure
    ```

    This updates `lib/firebase_options.dart` with the correct app IDs for each platform.

    <Info>
      Install the FlutterFire CLI once with `dart pub global activate flutterfire_cli` if you haven't already.
    </Info>
  </Step>

  <Step title="Run the app">
    Start the development server. Use the `-d chrome` flag to target the web renderer, which is the fastest way to verify the full storefront experience locally.

    ```bash
    flutter run -d chrome
    ```

    For mobile targets, connect a device or start an emulator, then run `flutter run` without the `-d` flag to select from available devices.
  </Step>

  <Step title="Open your storefront">
    Once the app is running, navigate to your business slug in the browser:

    ```
    http://localhost:<port>/<businessSlug>
    ```

    The storefront loads the business record matching that slug from Firestore and renders the catalog with your products, filters, and branding.
  </Step>
</Steps>

<Note>
  If you don't have a business record in Firestore yet, create one with a `slug` field matching the URL segment you want to use (for example, `my-store`). The admin panel is accessible at `/<businessSlug>/admin` once Firebase Auth is configured.
</Note>
