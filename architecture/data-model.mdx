description: 'Field reference for all Virtual Catalog entities — Business, Product, ProductVariant, CartItem, Order, BannerItem — with Firestore collection structure.'
---

Virtual Catalog organizes its data around two top-level Firestore collections — `businesses` and `products` — plus an `orders` collection that is mirrored into a per-business subcollection for efficient admin queries. Every entity in the domain layer is a plain Dart class with no Firebase dependencies; Firestore-specific serialization lives exclusively in the model classes under `lib/data/models/`.

## Multi-tenancy model

Each storefront is identified by its **slug** — a short, URL-safe string chosen at business creation time. The slug serves as the Firestore document ID in the `businesses` collection and as the `businessId` field on every product. This means:

- `businesses/{slug}` — the single document for a storefront's configuration.
- `products` (root collection) — queried with `where("businessId", isEqualTo: slug)` to scope results to one storefront.
- `businesses/{slug}/orders` — subcollection for fast admin dashboard queries.

<Info>
There is no numeric primary key. The slug is both the human-readable URL segment (`/:businessSlug`) and the Firestore document ID.
</Info>

  <Accordion title="Business">

The root entity for a storefront. One document per slug in the `businesses` collection.

```dart lib/domain/entities/business.dart
class Business {
  final String slug;
  final String ownerId;
  final String name;
  final String description;
  final String logoUrl;
  final String whatsappNumber;
  final List<BannerItem> banners;
  final List<DeliveryMethod> deliveryMethods;
  final List<PaymentMethod> paymentMethods;
  final bool showDesktopLogo;
  final bool showMobileLogo;
  final String? termsAndConditions;
  final List<HomeBlock> homeBlocks;
  final String? izipayUsername;
  final String? izipayPassword;
  final String? izipayPublicKey;
  final String? themeColorHex;
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `slug` | `String` | Yes | Firestore document ID; used in all URLs |
| `ownerId` | `String` | Yes | Firebase Auth UID of the business owner |
| `name` | `String` | Yes | Display name, also set as the browser page title |
| `description` | `String` | Yes | Short storefront description |
| `logoUrl` | `String` | Yes | Cloudinary or public image URL; also set as the favicon |
| `whatsappNumber` | `String` | Yes | Used for WhatsApp payment and contact links |
| `banners` | `List<BannerItem>` | Yes | Hero carousel slides |
| `deliveryMethods` | `List<DeliveryMethod>` | Yes | Available shipping/pickup options |
| `paymentMethods` | `List<PaymentMethod>` | Yes | Accepted payment types |
| `showDesktopLogo` | `bool` | No | Defaults to `true` |
| `showMobileLogo` | `bool` | No | Defaults to `true` |
| `termsAndConditions` | `String?` | No | Markdown or plain text; the `/:slug/terms` route redirects to home when this is null or empty |
| `homeBlocks` | `List<HomeBlock>` | No | Ordered list of product blocks on the home page; defaults to `[]` |
| `izipayUsername` | `String?` | No | Izipay merchant credentials |
| `izipayPassword` | `String?` | No | Izipay merchant credentials |
| `izipayPublicKey` | `String?` | No | Izipay public key for client-side tokenization |
| `themeColorHex` | `String?` | No | Hex string (e.g. `#E53935`) used to seed the Material color scheme |

  <Accordion title="Product">

Stored in the root `products` collection. Scoped to a business via `businessId`.

```dart lib/domain/entities/product.dart
class Product {
  final String id;
  final String businessId;
  final String? sku;
  final String name;
  final String description;
  final DateTime createdAt;
  final DateTime updatedAt;
  final String category;
  final bool isAvailable;
  final int salesCount;
  final List<String> imageUrl;
  final List<ProductVariant> variants;
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `id` | `String` | Yes | Auto-generated Firestore document ID |
| `businessId` | `String` | Yes | Equals the business `slug`; used as the Firestore filter |
| `sku` | `String?` | No | Optional merchant stock-keeping unit |
| `name` | `String` | Yes | Product display name |
| `description` | `String` | Yes | Full product description |
| `createdAt` | `DateTime` | Yes | Timestamp set on first write |
| `updatedAt` | `DateTime` | Yes | Timestamp updated on every edit |
| `category` | `String` | Yes | Free-text category; products are sorted by category in `ProductProvider` |
| `isAvailable` | `bool` | No | Defaults to `true`; hidden from catalog when `false` |
| `salesCount` | `int` | No | Defaults to `0`; used for "best selling" sort in `HomeBlock` |
| `imageUrl` | `List<String>` | Yes | Ordered list of image URLs (Cloudinary recommended) |
| `variants` | `List<ProductVariant>` | Yes | At least one variant is expected |

  </Accordion>

  <Accordion title="ProductVariant">

Embedded inside each `Product` document as a list — not a separate Firestore collection.

```dart lib/domain/entities/product_variant.dart
class ProductVariant {
  final String? sku;
  final String name;
  final int? color;
  final int stock;
  final List<String> sizes;
  final double price;
  final double? discountPrice;
}
```

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `sku` | `String?` | No | Optional variant-level SKU |
| `name` | `String` | Yes | Variant label (e.g. "Azul marino", "Talla única") |
| `color` | `int?` | No | ARGB color integer for color-swatch UI |
| `stock` | `int` | Yes | Current inventory count; `CartProvider` enforces this as the max quantity |
| `sizes` | `List<String>` | Yes | Available size labels (e.g. `["S", "M", "L"]`); empty list means no size selection |
| `price` | `double` | Yes | Regular selling price |
| `discountPrice` | `double?` | No | Sale price; when set, takes precedence over `price` in cart calculations |

  </Accordion>

  <Accordion title="CartItem">

An in-memory entity — never written to Firestore. Persisted locally per-business using `SharedPreferences` (key: `cart_{slug}`).

```dart lib/domain/entities/cart_item.dart
class CartItem {
  Product product;
  ProductVariant variant;
  String size;
  int quantity;

  // Computed getters
  double get unitPrice        => variant.discountPrice ?? variant.price;
  double get originalUnitPrice => variant.price;
  double get subTotal         => unitPrice * quantity;
  double get originalSubTotal => originalUnitPrice * quantity;
  bool   get hasDiscount      => variant.discountPrice != null;
  double get savings          => originalSubTotal - subTotal;
}
```

| Field / Getter | Type | Notes |
|----------------|------|-------|
| `product` | `Product` | Full product snapshot at time of add-to-cart |
| `variant` | `ProductVariant` | The selected variant |
| `size` | `String` | The selected size label |
| `quantity` | `int` | Mutable; capped at `variant.stock` by `CartProvider` |
| `unitPrice` | `double` (computed) | `discountPrice` if present, otherwise `price` |
| `originalUnitPrice` | `double` (computed) | Always `price`, regardless of discounts |
| `subTotal` | `double` (computed) | `unitPrice × quantity` |
| `originalSubTotal` | `double` (computed) | `originalUnitPrice × quantity` |
| `hasDiscount` | `bool` (computed) | `true` when `variant.discountPrice != null` |
| `savings` | `double` (computed) | `originalSubTotal − subTotal` |

<Tip>
`CartProvider` supports two checkout modes: `CartMode.buyNow` (single item, bypasses the cart) and `CartMode.buyCart` (all cart items proceed to checkout). Both modes populate `_checkoutItems` before navigating to `/:slug/checkout`.
</Tip>

  </Accordion>

## Firestore collection map

```
firestore/
├── businesses/
│   └── {slug}/                     ← Business document (ID = slug)
│       └── orders/
│           └── {orderId}/          ← Order subcollection (mirrored from root)
├── products/
│   └── {productId}/                ← businessId field scopes to a slug
└── orders/
    └── {orderId}/                  ← Global order collection for real-time status polling
```

<Warning>
Products are not stored as a subcollection of `businesses`. They live in the root `products` collection and are filtered by `businessId`. Querying without the `businessId` filter returns products from all businesses.
</Warning>
